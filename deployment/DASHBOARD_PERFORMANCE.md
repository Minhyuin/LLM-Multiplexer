# 队内面板性能优化（第一、二阶段）

## 行为

首屏只渲染筛选项和模块占位，不聚合 UsageLog；进入面板也不再触发上游自动同步，数据新鲜度依赖既有后台同步和手动同步。统计总览、个人概览、趋势与模型、排行榜、队员用量、错误记录、管理补充信息分别通过已登录的只读接口加载。浏览器最多两个请求并发；筛选变更取消旧请求并用请求代次防止旧结果覆盖；模块失败可单独重试。队员用量表每页 25 条，最高使用模型仅对当前页计算。个人模型占比保留无坐标轴的饼图；错误模型分布按错误次数计算。全部历史和超过 180 天的自定义区间按月绘制趋势。

数据读取继续应用原来的时间、分组、年级和可见性条件，个人概览按当前有效账号计算。管理模块及视角切换权限有回归测试。模块响应 private/no-store，不采用第三阶段的统计缓存。

## 后端

aggregate_dashboard(queryset, trend_bucket="day", *, sections=None, key_page=None, key_page_size=25) 支持按需聚合；未传 sections 时保留原来的完整数据结构。总览计数和金额合为一次聚合。趋势的缓存和思考 Token 继续按历史 raw_payload 的路径优先级计算，常见值在数据库内聚合；Unicode 数字、超长数值等特殊行单独流式读取并按 Python 旧规则计算。数据库表达式不可用或执行失败时回退原扫描并记录警告，不改变统计口径。

本次没有增加数据库表、索引、迁移或生产依赖。PostgreSQL 表达式已做解析检查和测试代码准备，但尚未连接实际 PostgreSQL 执行验证。发布前必须在隔离 PostgreSQL 数据库执行 DSN 测试，并对真实规模的只读查询执行计划和耗时进行验证；本地 SQLite 的提升不能作为生产 SLA。

## 验证与发布

包含首页图片展示回归的完整 Django 测试 155 项通过，2 项 PostgreSQL 集成测试因未提供 DSN 跳过。Django check、makemigrations --check --dry-run、git diff --check 通过。浏览器验收使用真实 Django Client 响应和 Edge，按 1440、768、390 像素宽度验证模块加载、分页、图表、溢出、失败重试和筛选竞态；173 项浏览器及接口检查全部通过，详细结果记录在工作区 portal-dashboard-review/results.json。竞态测试验证了请求取消和筛选代次保护；由于两请求并发上限和同步路由拦截，尚未模拟旧响应晚于新响应到达的精确时序。截图使用模拟账号和数据，不代表生产数据，也未进行人工像素审阅。

本次按用户授权，基于真实远端 main 历史提交面板优化和首页图片展示。main 推送触发既有 CI 和自动发布链路；不推送本地合成开发历史。PostgreSQL 实际执行和真实规模性能验证仍未完成，发布后需继续核查统计结果及查询日志。
