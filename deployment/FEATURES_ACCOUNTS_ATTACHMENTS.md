# 账户视角与私有附件部署说明

本次功能在本地开发验收后交付。发布前需执行新增附件表迁移，并配置持久化私有存储。

## 管理员账户视角

管理员在成员管理中进入目标账户视角。视角保留原管理员的认证身份，每次请求重新验证管理员权限，并使用目标账户的权限和数据范围渲染页面。视角为只读；页面顶部提供返回管理员入口。退出登录终止会话。无需知道或更改目标账户密码。

## 附件存储

公告和讨论附件由 Django 权限端点读取，不能增加 nginx 公开 alias。`PRIVATE_UPLOAD_ROOT` 必须与公开的 `MEDIA_ROOT` 分开。

Docker Compose 已提供仅挂载到 web 服务的 `private_uploads_volume`。采用发布目录切换的生产环境，必须在共享环境配置中设置：

```dotenv
PRIVATE_UPLOAD_ROOT=/root/pioneer-portal.shared/private_uploads
```

提前创建该目录并确保运行门户的服务用户可以读写。不要把该目录放在某一个版本的 release 目录中，以免版本清理删除上传内容；无需修改 nginx 媒体别名。

附件表和磁盘文件需要一起备份；数据库备份不包含文件内容。恢复时保留文件名和相对路径，恢复至配置的私有目录。

## 发布与回退

1. 本地和 CI 运行完整测试与 `makemigrations --check --dry-run`。
2. 发布前配置私有目录；备份门户数据库，确认已有备份策略覆盖附件目录。
3. 在与生产一致的数据库上检查迁移计划并执行 `python manage.py migrate --noinput`；当前发布网关关闭了自动迁移，不能依赖它替代此步骤。
4. 按既有自动发布流程部署。检查管理员进入/退出视角、普通成员上传、图片预览、附件下载，以及匿名访问和草稿公告附件的拒绝结果。
5. 代码回退使用先前 release，保留新增附件表和私有目录；不要自动反向迁移，否则会删除附件记录。恢复数据库和文件只在需要恢复数据时进行。

本说明与 Compose 配置仅影响后续发布准备，开发阶段不操作生产服务器。
